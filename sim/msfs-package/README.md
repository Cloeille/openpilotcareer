# OpenPilotCareer toolbar panel for MSFS 2020 / 2024

An in-sim toolbar panel (HTML/CSS/JS, dark, EFB-style, 18 px base text) that shows:

- the current job (from → to, aircraft),
- the flight phase (preflight, taxi out, airborne, landed, parked),
- the verification status (pending / verified / rejected + reason),
- the anti-cheat flags.

It is a **companion UI only**. The bridge decides everything; the panel polls `GET http://127.0.0.1:7878/status`
every 2 s and draws what it gets. Offline bridge shows "Bridge not running"; a bad answer shows
"Bridge status unreadable". Status is never colour-only (every state has a glyph and a text label).

> **Status: not tested in the simulator.** It has only been run in a normal browser against the mock server
> below, and through unit tests. See [Unverified](#unverified).

## Layout

```
openpilotcareer-panel/            <- the package you copy into Community
  manifest.json
  layout.json                     <- generated by build-layout.js
  html_ui/InGamePanels/OpenPilotCareer/
    OpenPilotCareer.html|.css|.js   sim glue (follows the community toolbar-panel template)
    panel.js                        DOM rendering + polling (no framework)
    view-model.js                   pure mapper: status JSON -> display state
  html_ui/Textures/Menu/toolbar/ICON_TOOLBAR_OPENPILOTCAREER_PANEL.svg
  InGamePanels/openpilotcareer-panel.spb  <- NOT in git: compiled from spb-project/ (step 1 below)
spb-project/                      <- Package Tool project that compiles the .spb
build-layout.js                   <- generates layout.json (Node, no deps)
mock/                             <- browser mock page + mock bridge status server
test/                             <- node:test suites
docs/                             <- screenshots of the mock page
```

## Develop and test (any OS; no dependencies; run with Node 26.7, the version used here)

```
cd sim/msfs-package
npm test                       # or: node --test "test/*.test.js"
node mock/mock-status-server.js    # then open http://127.0.0.1:7878/
curl "http://127.0.0.1:7878/scenario?name=rejected"   # switch scenario
```

Scenarios: `preflight`, `taxi-pending`, `airborne-pending`, `verified`, `rejected`, `flags`, `no-job`,
`offline` (socket dropped), `malformed`, `bad-contract`, `bad-http`. The mock serves the real package files, so what
you see is the real panel code. Port 7878 is hard-wired in the panel; stop the real bridge first if it is running.

Screenshots (mock page, browser, 560 px column): [airborne/pending](docs/mock-airborne-pending.png),
[rejected](docs/mock-rejected.png), [3 flags](docs/mock-flags.png), [bridge offline](docs/mock-offline.png).

Tests: `view-model.test.js` (mapping incl. offline/malformed/contract violations), `contrast.test.js`
(WCAG AA ratios of the CSS palette), `build-layout.test.js` (sizes, FILETIME, drift check),
`mock-contract.test.js` (mock scenarios map to the states they promise).

## Build the package

1. **Compile the `.spb` (Windows, MSFS SDK installed).** The toolbar button is defined by an `InGamePanels` XML
   (`spb-project/PackageSources/openpilotcareer-panel.xml`) that the sim's Package Tool compiles to a binary `.spb`.
   This step is a copy of the community template's procedure and **could not be run here** (no SDK, no sim):
   ```
   "%MSFS_SDK%\Tools\bin\fspackagetool.exe" spb-project\OpenPilotCareerPanel.xml -nomirroring
   mkdir openpilotcareer-panel\InGamePanels
   copy /Y spb-project\Packages\openpilotcareer-panel\Build\openpilotcareer-panel.spb openpilotcareer-panel\InGamePanels
   ```
   The `.spb` file name here mirrors the template's `build.bat` (it is named after the asset group). If your SDK
   writes a different name, copy whatever `.spb` it produced into `openpilotcareer-panel/InGamePanels/`.
2. **Generate `layout.json`:** `node build-layout.js` (writes exact byte sizes and Windows FILETIME dates for every file
   except `layout.json` and `manifest.json`). It warns if no `.spb` is present. `node build-layout.js --check` fails when
   `layout.json` paths/sizes no longer match the files; re-run the script after editing any package file or adding the `.spb`.

## Install

Copy the whole `openpilotcareer-panel` folder into a Community folder, then start the sim. Start the OpenPilotCareer
bridge before (or after) the sim; the panel retries every 2 s.

- **MSFS 2020:** copy into `Community`. To find the folder: Developer Mode → Tools → Virtual File System → Packages Folders →
  *Open Community Folder* (needs Developer Mode on).
- **MSFS 2024:** the SDK describes two folders: `Community` (for MSFS 2020 packages) and `Community2024` (for 2024
  packages), opened from the same Virtual File System window via *Open Community 2024 Folder*. Per the 2024 VFS page,
  `Community` is shared with MSFS 2020 and putting 2024 packages there is not recommended. So install into
  `Community2024`. The exact folder path depends on the store (Steam/MS Store) and is stored in `UserCfg.opt`
  (`InstalledPackagesPath`).
- Open the toolbar in a flight; the panel should appear as a toolbar item named "OpenPilotCareer". If the button does
  not show, check that the `.spb` exists in `InGamePanels/` and that `layout.json` lists it (the build script prints a
  warning otherwise).

Uninstall: delete the folder.

## SDK facts: what was read, and where

Read in the official docs (fetched while writing this):

- A package is a folder with `layout.json` (lists all other files) and `manifest.json` (metadata) at its top level;
  user packages go in the Community folder. 2020: <https://docs.flightsimulator.com/html/Introduction/Using_The_SDK.htm>;
  2024: <https://docs.flightsimulator.com/msfs2024/flighting/introduction/using-the-sdk/>
- Finding the Community folder in 2020: <https://docs.flightsimulator.com/html/Introduction/SDK_Overview.htm>
- 2024 has `Community` (for MSFS 2020 packages) and `Community2024` (for MSFS 2024 packages), opened from the Virtual File
  System window: <https://docs.flightsimulator.com/msfs2024/flighting/introduction/sdk-overview/>
- 2024 folder roles table, "not recommended" note for 2024 packages in `Community`, `UserCfg.opt` /
  `InstalledPackagesPath`: <https://docs.flightsimulator.com/msfs2024/flighting/devmode/menus/tools_info/virtual-file-system/virtual-file-system-information>

Read in the official docs, and they do **not** cover this package type:

- Both "Using The SDK" pages say UI is "not customisable as part of add-ons". The only toolbar-panel page found,
  <https://docs.flightsimulator.com/html/Programming_Tools/JavaScript/Coherent_Listeners/JS_LISTENER_TOOLBAR_PANELS.htm>,
  is marked work in progress with empty descriptions. The Package Tool XML page
  (<https://docs.flightsimulator.com/html/Additional_Information/Tools/Package_Tool/Package_Tool_XML_Definitions.htm>) lists
  `ContentType` values MISSION, AIRCRAFT, INSTRUMENTS, LIVERY, SCENERY, MISC (no SPB) and says package XML should normally
  come from the Project Editor.
- So the toolbar-panel mechanism here (`InGamePanels` XML → `.spb`, `ingame-ui` element, `ICON_TOOLBAR_*` icon,
  `fs-base-ui` / `fs-base-propdefs` / `asobo-vcockpits-core` dependencies, `/JS/*` and `/templates/*` includes) is copied from
  community material, **not from the SDK docs**:
  <https://github.com/bymaximus/msfs2020-toolbar-window-template> (MSFS 2020 template; file layout, `build.bat`, XML, manifest)
  and the forum thread <https://devsupport.flightsimulator.com/t/panel-not-showing-in-toolbar-despite-correct-layout-json-and-mounted-package/17375>
  (a forum answer that the `.spb` is mandatory and that panels fail silently when anything is wrong) and
  <https://devsupport.flightsimulator.com/t/in-game-panels/16981> (a report that the 2020 template built for 2024 but displayed nothing useful).

## Unverified

Everything below is **unverified** (nothing here ran inside MSFS):

- That the panel loads, shows a toolbar button, and renders in MSFS 2020 or MSFS 2024. The 2024 behaviour of the 2020-era
  template is only known from forum reports (some report it needs adjustment in 2024).
- That the `.spb` compile steps above work as written, including the `ContentType` `SPB` project settings and the output file name.
- `manifest.json`: `content_type` is empty and the three dependency versions are copied from the community template; the
  correct values for 2020 vs 2024 are not documented in what was read. `minimum_game_version` `1.8.3` is also from the template.
- That the sim's UI engine accepts the CSS/JS used (`panel.js`/`view-model.js` are ES5, CSS avoids variables and flex `gap` as a
  precaution; the sim glue uses `class` syntax like the template).
- **Cross-origin access to the bridge.** The panel's page origin inside the sim is unknown, so the browser XHR to
  `http://127.0.0.1:7878/status` needs the bridge to answer with `Access-Control-Allow-Origin` (the mock does). The mock page is same-origin,
  so it does not exercise this. Whether the sim blocks plain-HTTP loopback requests is untested.
- Toolbar icon appearance, default panel size, and panel behaviour while the sim is paused (the panel listens to the template's
  `panelActive` / `panelInactive` events, and also starts polling at load).
- Screen-reader behaviour in the sim (ARIA roles/live region are standard but untested there).
- The FILETIME `date` values in `layout.json` use the format seen in the community template; the SDK pages read do not define it.
